# 출입 권한 검증 TC 자동화 (개인 학습)

연습용 출입 관리 웹앱의 출입 권한 TC 4건을 Playwright(Python)와 pytest로 자동화했습니다.
출입 그룹 → 문 + 허용 시간으로 권한을 판단하는 구조는 BioStar 2의 공개된 출입 권한 개념을 참고했고,
요구사항과 메시지 번호(E-001 등)는 학습을 위해 직접 만든 가상 사양입니다.

## 검증 범위
- 단말기 인증(지문, 얼굴, 카드)은 "인증된 사번"을 입력하는 것으로 대신합니다.
- 인증 이후의 **권한 판단**, **문 상태**, **이벤트 로그 기록**을 검증합니다.

## 요구사항 (가상)
| ID | 요구사항 |
|---|---|
| R1 | 사용자 등록 시 출입 그룹을 지정한다 (정문 / 연구동) |
| R2 | 정문 그룹은 정문만, 연구동 그룹은 정문과 연구동에 출입할 수 있다 |
| R3 | 연구동 문은 09:00~18:00에만 출입할 수 있다 (09:00, 18:00 포함) |
| R4 | 출입 시도 결과는 이벤트 로그에 기록된다. 최신 기록이 맨 위에 표시된다 |

| 결과 | 화면 문구 | 문 상태 |
|---|---|---|
| 허용 | 출입 허용 | 열림 |
| E-001 | 등록되지 않은 사용자입니다 | 잠김 |
| E-002 | 출입 권한이 없습니다 | 잠김 |
| E-003 | 출입 허용 시간이 아닙니다 | 잠김 |

## TC 목록
| TC | 내용 | 관련 요구사항 |
|---|---|---|
| ACC-01 | 연구동 그룹 사용자의 연구동 출입 → 허용 | R1, R2, R4 |
| ACC-02 | 정문 그룹 사용자의 연구동 출입 → E-002 거부 | R2, R4 |
| ACC-03 | 허용 시간 끝 경계값: 18:00 허용 / 18:01 E-003 거부 | R3, R4 |
| ACC-04 | 사용자 삭제 후 같은 사번으로 출입 → E-001 거부, 이전 기록 유지 | R2, R4 |

## 사양 확인 필요 사항
| 번호 | 질문 | QA 의견 | 상태 |
|---|---|---|---|
| Q-01 | 사용자를 삭제하면 기존 출입 로그도 삭제되는가? | 보안 감사를 위해 일정 기간 유지 후 삭제(또는 익명화)를 제안 | 가정 적용 (로그 유지) |

## 파일 구성
| 파일 | 내용 |
|---|---|
| practice_app.html | 테스트 대상 연습용 웹앱 (사용자 등록·삭제, 출입 시도, 문 상태, 이벤트 로그) |
| TC_출입권한_연습.xlsx | TC 4건, 요구사항, 확인 필요 사항 |

## 실행 방법
```
pip install pytest-playwright
python -m playwright install chromium
python -m pytest                          # 전체 실행
python -m pytest --headed --slowmo 700    # 브라우저 화면을 보면서 천천히 실행
```

실행 환경: Windows, Python 3.15, Playwright 1.63, pytest 9.1

## 작업하며 정리한 것
- 허용 시간은 가운데 값(10:00)이 아니라 **경계값(18:00, 18:01)**으로 확인했습니다. "포함"을 "미만"으로 잘못 구현한 결함은 경계에서만 드러나기 때문입니다.
- 거부 결과는 "거부" 글자만이 아니라 **거부 코드(E-002 등)**까지 확인했습니다. 다른 사유로 거부돼도 통과하는 느슨한 검증을 피하기 위해서입니다.
- 이벤트 로그는 여러 줄이 쌓이므로, 개수는 전체로 세고(`to_have_count`) 내용은 최신 줄(`.first`)과 이전 줄(`.last`)을 지정해 확인했습니다.
- ACC-04에서 사용자 관리(삭제)가 출입 권한에 바로 반영되는지 확인해, 기능 간 연관성을 검증했습니다.
- 사양에 없는 동작(삭제된 사용자의 로그 처리)은 가정을 명시하고 확인 필요 사항(Q-01)으로 남겼습니다.
